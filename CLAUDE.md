# lyra-website — Project Context

The public website for the Lyra programming language: a **dev blog** plus **documentation and guides**. Built with [Astro](https://astro.build) and the [Starlight](https://starlight.astro.build) docs framework.

Package manager is **pnpm** (note `pnpm-lock.yaml` and `pnpm-workspace.yaml`). Use `pnpm`, not `npm`.

## Stack

- **Astro** `^6` — site framework
- **`@astrojs/starlight`** — documentation theme (sidebar nav, search, page layout)
- **`starlight-blog`** — adds the dev blog on top of Starlight
- **`rehype-tree-sitter`** — syntax-highlights fenced code blocks using the real Lyra tree-sitter grammar (see below)
- **`sharp`** — image optimization

## Commands

All run from `lyra-website/`:

```bash
pnpm install     # install dependencies
pnpm dev         # local dev server at http://localhost:4321
pnpm build       # production build → ./dist/
pnpm preview     # preview the production build locally
pnpm astro ...   # Astro CLI (e.g. `astro add`, `astro check`)
```

## Structure

```
astro.config.mjs            — Astro + Starlight config (integrations, sidebar, markdown pipeline)
src/
  content.config.ts         — content collections; `docs` collection extends the Starlight
                              schema with starlight-blog's blog schema
  content/docs/             — all pages; file path → route
    index.mdx               — landing page
    blog/                   — dev blog posts (e.g. why-lyra.md)
    guides/                 — guides, incl. guides/types/ (primitives, tuples)
    reference/              — reference docs (sidebar autogenerated from this dir).
                              std-prelude.md is GENERATED by `lyrac doc` — do not edit
  styles/night-owl-theme.css  — custom theme (Starlight's expressiveCode is disabled)
  assets/                   — images referenced from Markdown
public/                     — static assets served as-is (favicons, etc.)
```

Starlight renders any `.md`/`.mdx` under `src/content/docs/`. The sidebar is configured manually in `astro.config.mjs` (Guides + nested Types) except for the `reference/` section, which is `autogenerate`d from the directory.

## The standard library's reference page is generated

`src/content/docs/reference/std-prelude.md` is produced by `lyrac doc` from the `///`
comments in `lyra/std/prelude/*.lyra`. It carries a `<!-- Generated by … -->` notice.
**Edit the Lyra sources, not the page**, and regenerate:

```bash
cd ../lyra && ./build.sh
./build/lyrac doc std/prelude/prelude.lyra -o ../lyra-website/src/content/docs/reference --strict
```

Two things about it that are this repo's business rather than the compiler's:

- **The file name is `std-prelude.md`, not `std.prelude.md`.** Starlight derives the URL
  slug from the file name and *strips* dots, so the dotted form publishes at
  `/reference/stdprelude/`. The page's own title is the real dotted path, so nothing is
  lost. `docgen.FileName` is where that decision lives.
- **The frontmatter is emitted as quoted YAML scalars.** A module summary is prose and can
  contain a colon, which unquoted would parse as a nested mapping — and that failure shows
  up as a broken build *here*, not as an error in the compiler that wrote it.

The sidebar needs no change: `reference/` is `autogenerate`d, so a new module's page
appears on its own.

## Lyra Code Highlighting

Markdown's default syntax highlighting is **disabled** (`syntaxHighlight: false`, `expressiveCode: false`). Instead, `rehype-tree-sitter` highlights fenced code blocks using the actual Lyra grammar:

- `treeSitterGrammarRoot` points at the workspace root so it can load the `tree-sitter-lyra` grammar. It is resolved from the config file's own location via `fileURLToPath(new URL("..", import.meta.url))` — portable across machines and independent of cwd. This assumes the site stays nested one level below the workspace root (a sibling of `tree-sitter-lyra/`).
- `scopeMap` maps the ```` ```lyra ```` fence language to `source.lyra_parser`.

This means code samples in docs/blog posts stay in sync with the real grammar — changes to `tree-sitter-lyra/` affect how snippets render here.

## Relationship to Other Sub-Projects

- **`tree-sitter-lyra/`** — its grammar powers code-block highlighting via `rehype-tree-sitter`. No build-time package dependency; the grammar is loaded from the workspace path in `astro.config.mjs`.
- Otherwise independent of the Go compiler and VS Code extension.
