# lyra-website — Project Context

Public Lyra site: dev blog + docs/guides. [Astro](https://astro.build) with
[Starlight](https://starlight.astro.build). **Use `pnpm`, not `npm`.**

## Stack

- **Astro** `^7`, **`@astrojs/starlight`** (docs theme), **`starlight-blog`** (blog)
- **`rehype-tree-sitter`** — highlights code blocks with the real Lyra grammar
- **`sharp`** — image optimization

## Commands

From `lyra-website/`:

```bash
pnpm install
pnpm dev              # http://localhost:4321
pnpm build            # → ./dist/
pnpm preview
pnpm astro ...        # Astro CLI
pnpm check:snippets   # type-check every lyra snippet (below)
```

## Structure

```
astro.config.mjs          — Astro + Starlight config (integrations, sidebar, markdown)
src/
  content.config.ts       — `docs` collection = Starlight schema + starlight-blog schema
  content/docs/           — all pages; file path → route
    index.mdx             — landing page
    blog/                 — dev blog posts
    learn/                — the beginner track, read in order (getting started → cheat sheet)
    guides/               — topic guides, incl. guides/types/
    reference/            — sidebar autogenerated; std-prelude.md is GENERATED
  styles/lyra-brand.css   — brand theme (below)
  styles/night-owl-theme.css — code theme (expressiveCode disabled)
  assets/                 — images referenced from Markdown
public/                   — static assets
scripts/check-snippets.mjs
```

The sidebar is manual in `astro.config.mjs` (Learn Lyra, then Guides + nested Types), except
`reference/`, which is `autogenerate`d — a new module's page appears on its own.

## The Learn Lyra track (`learn/`)

For a programmer new to Lyra: each page builds on the one before, and the cheat sheet is the
reading companion that links back into them. **Keep it in step with the language** — when a
rule in `lyra/LANGUAGE.md` changes a form these pages teach, update the page. Teach only what
compiles *and runs*: `check:snippets` type-checks, but a form can type-check and still fail in
the backend, so run a new example with `lyrac run` before adding it.

## The std reference page is generated

`src/content/docs/reference/std-prelude.md` comes from `///` comments in
`lyra/std/prelude/*.lyra`. **Edit the Lyra sources, not the page**, then:

```bash
cd ../lyra && ./build.sh
./build/lyrac doc std/prelude/prelude.lyra -o ../lyra-website/src/content/docs/reference --strict
```

- File name is `std-prelude.md`, not `std.prelude.md` (route `/reference/std-prelude/`):
  Starlight strips dots from slugs. Decided in `docgen.FileName`.
- Frontmatter is quoted YAML scalars — a summary containing a colon would otherwise break
  the build here.

## Brand theme (`src/styles/lyra-brand.css`)

- Derived from `src/assets/lyra-mark.svg`: gold `hsl(38, 62%, 48%)`; hue 38 is the only hue.
  Restyle by overriding Starlight's `--sl-color-*` tokens, not per component.
- Headings are **Cinzel** (`@fontsource-variable/cinzel`).
- Contrast: light theme darkens the accent to `hsl(38, 72%, 34%)` (the mark's gold is 2.8:1
  on white); dark theme's filled button uses `--sl-color-accent` (not
  `--sl-color-text-accent`) with dark ink.

Starlight layout gotchas:

- **Linkable headings are `display: inline`** inside `div.sl-heading-wrapper.level-hN`, so
  section rules (`border-bottom`) go on the wrapper, not the `h2`.
- **Inline code is a chip**; in headings it is un-chipped and set smaller/lighter, else
  reference-page `h3` declarations outweigh their `h2` sections.
- **Cinzel sets lowercase as small caps**, so mixed-case headings look small.
  `text-transform: uppercase` is deliberately **not** applied (it would uppercase prose
  headings); one declaration in the file turns it on.

## Lyra code highlighting

`syntaxHighlight: false` and `expressiveCode: false`; `rehype-tree-sitter` highlights instead:

- `treeSitterGrammarRoot` is the workspace root, via
  `fileURLToPath(new URL("..", import.meta.url))` — assumes the site stays a sibling of
  `tree-sitter-lyra/`.
- `scopeMap` maps the `lyra` fence to `source.lyra_parser`.

Grammar changes in `tree-sitter-lyra/` change rendering here.

### Clear Astro's cache after a query change

Highlighted HTML is cached in `.astro/` and `node_modules/.astro/`, so an edit to
`tree-sitter-lyra/queries/highlights.scm` looks like a non-matching query until:

```bash
rm -rf .astro node_modules/.astro dist && pnpm build
```

### Every `lyra` snippet is type-checked

`pnpm check:snippets` runs `lyrac check` on every fenced `lyra` block under
`src/content/docs/`, failing on **errors and warnings** (parsing alone misses e.g. `lyra-W012`,
`lyra-W018`).

- **Fails hard if `lyrac` is missing.** Lookup: `$LYRAC`, `../lyra/build/lyrac`, `PATH`.
- **Preflights the prelude** (`let m: Maybe<i64> = None`), so a `lyrac` detached from its
  `build/std` symlink is reported as a toolchain problem, not a docs one.
- **Exemptions:** `reference/` is skipped (generated signatures). Otherwise put
  `<!-- lyra:no-check -->` on the line directly above the fence (currently only the ECS block
  in `blog/why-lyra.md`).

Rebuild the compiler (`cd ../lyra && ./build.sh`) before trusting a run; a newly failing
snippet may be a compiler gap rather than a doc bug.

## Relationship to Other Sub-Projects

- **`tree-sitter-lyra/`** — loaded from the workspace path for highlighting; no package dependency.
- **`lyra/`** — `lyrac` generates the reference page and checks snippets.
